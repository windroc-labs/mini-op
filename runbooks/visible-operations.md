# Visible mini operation inventory

Source: WDRC-156. Covers mini-side operations in `mini/`, `ctl/`, all runbooks and `host/README.md`, and the kinds of operation projects' runbooks run (for ensemble: its test accounts, install and cleanup). Container builds, configuration, proxy setup and file preparation on the host do not run on the mini.

**Visible first:** public commands (both text and output confirmed free of secrets) use `mini exec`; interactive commands use `mini run`; ordinary pages use `o` in the foreground. SSH only transports data, controls helpers, reads results or handles an exception with a reason below. Secrets travel through stdin or private files; page secrets use only `secfield`. Credential commands, raw API replies and unknown third-party output are not public commands.

## Results and recovery

`printf '%s\n' 'public command' | mini exec 60` runs a separate zsh file with noninteractive stdin from `/dev/null`. Terminal shows the command and output; complete streams return separately, with an SSH stderr status frame independent of the command's status. Script `exit`, syntax errors and status 255 are not mistaken for transport failure; a lost connection reports completion unknown.

On 124, use the printed id with `mini exec --collect <id>` to collect without rerunning. No completion file still returns 124; corrupt results return 1 and preserve evidence. Completion removes the job directory. If the connection failed before returning an id, use SSH only to read job directory names under `~/apm/state/visible/`, then collect; do not send the original command again. Remove only that id's directory after confirming an unstarted or abandoned job is no longer running. Drive one job at a time and never collect the same job concurrently.

For interaction, use README's mini run/--to/termwait; the final 25 lines are only for prompt inspection. Private command stdout stays out of exec, Terminal and logs. If received exec stdout/stderr might contain nonpublic data, capture it in a local 0600 file first.
